Introduction to JavaScript

Not Attempted

JavaScript was created in May 1995 by Brendan Eich at Netscape Communications in just 10 days, initially under the code name Mocha, renamed to LiveScript, and finally released as JavaScript to capitalize on the buzz surrounding Sun Microsystems' Java. It was standardized under the ECMAScript specification (ECMA-262).

1. Language Characteristics & Execution Paradigm

  • Single-Threaded & Non-Blocking: JavaScript has a single call stack and executes one command at a time. Concurrency is handled asynchronously via the Event Loop.
  • Dynamically Typed: Variables hold values of any type, and types are resolved at runtime rather than compile time.
  • First-Class Functions: Functions are treated as first-class citizens: they can be assigned to variables, passed as arguments to other functions (callbacks), and returned from functions (closures).
  • Multi-Paradigm: Supports imperative, functional, and prototype-based object-oriented programming.

2. Variable Declarations: var vs let vs const

Keyword Scope Hoisting Behavior Re-declaration? Re-assignment?
var Function scope Hoisted to top of scope and initialized with undefined. Yes Yes
let Block scope { ... } Hoisted to top of block, but enters the Temporal Dead Zone (TDZ) until execution reaches declaration. No Yes
const Block scope { ... } Hoisted into TDZ; must be initialized immediately at declaration. No No (reference is immutable, but object properties can still mutate)

3. Closures and the Event Loop

A Closure is the combination of a function bundled together with references to its surrounding lexical environment. A closure gives an inner function access to an outer function's scope even after the outer function has returned.

JavaScript Closure Pattern Example JavaScript 
function createCounter(initialValue) {
  let count = initialValue; // Private state held in closure

  return {
    increment: function() {
      count += 1;
      return count;
    },
    decrement: function() {
      count -= 1;
      return count;
    },
    getValue: function() {
      return count;
    }
  };
}

const counter = createCounter(10);
console.log(counter.increment()); // 11
console.log(counter.getValue());   // 11
console.log(counter.count);        // undefined (encapsulated)

Objects in JavaScript

Not Attempted

Unlike classical class-based object-oriented languages (Java, C++), JavaScript is fundamentally prototype-based. Every object in JavaScript contains an internal hidden link to another object, known as its prototype (accessible via Object.getPrototypeOf(obj) or legacy __proto__).

1. The Prototype Chain and Inheritance

When a property or method is accessed on an object, the JavaScript engine first checks the object itself (own property). If not found, it traverses up the prototype link to the parent prototype object, repeating this search until finding the property or reaching null at the end of the chain (Object.prototype.__proto__ === null). If not found, it returns undefined.

Prototypal Inheritance vs ES6 Classes JavaScript 
// 1. Classic Constructor Function & Prototype Linking
function Student(name, rollNo) {
  this.name = name;
  this.rollNo = rollNo;
}

Student.prototype.study = function() {
  return `${this.name} (Roll: ${this.rollNo}) is studying Web Technology CS35302.`;
};

// 2. Modern ES6 Class Syntax (Syntactic Sugar over Prototypal Inheritance)
class EngineeringStudent extends Student {
  constructor(name, rollNo, branch) {
    super(name, rollNo);
    this.branch = branch;
  }

  getDetails() {
    return `${this.study()} Branch: ${this.branch}`;
  }
}

const s1 = new EngineeringStudent("Aryan", 1045, "CSE");
console.log(s1.getDetails());

2. The this Keyword Binding Rules

  1. Default Binding: Standalone function invocation in non-strict mode binds this to the global object (window in browsers); in strict mode ("use strict"), this evaluates to undefined.
  2. Implicit Binding: When a function is called as a method of an object (obj.method()), this points to the object preceding the dot.
  3. Explicit Binding: Using .call(thisArg, arg1, ...), .apply(thisArg, [args]), or .bind(thisArg) forcibly sets the value of this.
  4. New Binding: When invoked with the new operator, a brand new empty object is created, its prototype is linked to the constructor's prototype, and this is bound to that new instance.
  5. Arrow Functions: Arrow functions do NOT have their own this; they capture this lexically from their enclosing scope.

Dynamic HTML with JavaScript

Not Attempted

Dynamic HTML (DHTML) represents the technique of manipulating the browser's Document Object Model (DOM) at runtime using JavaScript to create interactive, animated, responsive user interfaces without requiring complete page reloads.

1. Core DOM Manipulation Primitives

  • Querying Elements: document.getElementById('id'), document.querySelector('.class'), document.querySelectorAll('div > p') (returns static NodeList).
  • Creating & Inserting Nodes: document.createElement('div'), document.createTextNode('text'), parent.appendChild(node), parent.insertBefore(newNode, refNode), element.insertAdjacentHTML('beforeend', markup).
  • Modifying Content & Attributes: element.textContent = 'Safe string', element.setAttribute('data-id', '42'), element.classList.add('active'), element.classList.toggle('open').

2. Event Propagation: Capturing, Target, and Bubbling

When a user clicks an element nested deep inside the DOM, the event travels through three distinct phases:

  1. Capture Phase (Trickling): The event descends from window → document → <html> → <body> down to the target's parent.
  2. Target Phase: The event reaches the actual element clicked (e.target).
  3. Bubbling Phase: The event ascends back up the ancestor tree to window. (Default listener phase unless capture: true is passed).
High-Performance Event Delegation Pattern JavaScript 
// Instead of attaching 1,000 listeners to 1,000 list items:
const syllabusList = document.getElementById('syllabus-topic-list');

syllabusList.addEventListener('click', function(event) {
  // Find closest list item clicked
  const item = event.target.closest('li[data-topic-id]');
  if (!item) return;

  const topicId = item.getAttribute('data-topic-id');
  console.log(`User clicked topic: ${topicId}`);
  
  // Toggle selection state
  item.classList.toggle('selected');
});

HTML Lists, Tables, Images, Forms, Frames

Not Attempted

HTML provides structured markup elements to organize tabular data, hierarchical lists, media assets, interactive forms, and nested browsing contexts.

1. HTML Lists

  • Unordered List (<ul>): Bulleted collection of items (<li>).
  • Ordered List (<ol>): Numbered sequence of items; supports attributes type="1|a|A|i|I", start="10", reversed.
  • Description List (<dl>): Key-value pairings using description terms (<dt>) and description definitions (<dd>).

2. Accessible Tabular Data

Tables should never be used for page layout (use CSS Grid/Flexbox instead). Tables must structure relational data using semantic tags: <table>, <caption>, <thead>, <tbody>, <tfoot>, <tr>, <th scope="col|row">, and <td>. Span attributes:

  • colspan="N": Merges cell across N consecutive columns.
  • rowspan="N": Merges cell vertically across N consecutive rows.

3. Responsive Images: <picture> and srcset

Modern HTML5 provides the <picture> element to deliver the most efficient image format (e.g., AVIF, WebP) and pixel dimensions based on the client device screen density and viewport width:

Art Direction with HTML5 <picture> HTML5 
<picture>
  <source media="(min-width: 1024px)" srcset="banner-large.webp" type="image/webp" />
  <source media="(min-width: 640px)" srcset="banner-medium.webp" type="image/webp" />
  <img src="banner-fallback.jpg" alt="Quantum University WebTech Lab" loading="lazy" width="800" height="400" />
</picture>

4. HTML5 Forms and Constraint Validation

Forms collect user input via input controls: type="text|email|password|number|date|color|file|range". HTML5 enables native client-side validation using attributes: required, pattern="[A-Z]{5}[0-9]{4}[A-Z]{1}" (regex validation), min, max, maxlength. Controls are grouped using <fieldset> and labeled with <legend>.

5. Frames and the Modern <iframe>

Legacy HTML 4 <frameset> and <frame> are obsolete and completely removed in HTML5. Modern web development exclusively utilizes <iframe> (Inline Frame) to embed external content (maps, video players, payment gateways). For security against Cross-Site Scripting (XSS) and Clickjacking, always configure the sandbox attribute:

🔒
Security Hardening: The iframe Sandbox Writing <iframe sandbox src="..."> imposes maximum restrictions: disables scripts, blocks form submissions, prevents same-origin access, and forbids top-level navigation. Privileges can be selectively granted using tokens like sandbox="allow-scripts allow-forms allow-same-origin".

CSS (Cascading Style Sheets)

Not Attempted

Cascading Style Sheets (CSS) is the declarative style language used to describe the presentation, layout, typography, colors, and responsive adaptation of a document written in HTML or XML.

1. The Cascade and Specificity Formula

When multiple CSS rules conflict on the same element, the browser computes rule priority based on Importance (!important), Origin (User Agent → User → Author), and Specificity:

  • Inline Styles (style="..."): Specificity value: (1, 0, 0, 0).
  • ID Selectors (#header): Specificity value: (0, 1, 0, 0).
  • Class, Attribute, and Pseudo-classes (.btn, [type="text"], :hover): Specificity value: (0, 0, 1, 0).
  • Element & Pseudo-elements (h1, p, ::before): Specificity value: (0, 0, 0, 1).
  • Universal selector (*) and combinators (+, >, ~) add zero specificity.

2. The CSS Box Model

Every HTML element is rendered as a rectangular box comprising four concentric layers:

  • Content: The text or media rendered.
  • Padding: Transparent spacing immediately surrounding the content.
  • Border: Outermost boundary surrounding the padding.
  • Margin: Spacing outside the border separating this element from siblings.
💡
Best Practice: Reset to Border-Box By default, box-sizing: content-box causes width to apply only to content, meaning adding padding and borders makes the element wider than specified. Applying * { box-sizing: border-box; } forces width to include content, padding, and border, making responsive layouts predictable!

3. Modern Layout Systems: Flexbox vs Grid

  • CSS Flexbox (1-Dimensional Layout): Designed for laying out items in a single direction (row or column). Key container properties: display: flex, flex-direction, justify-content (main axis alignment), align-items (cross axis alignment), flex-wrap.
  • CSS Grid (2-Dimensional Layout): Designed for simultaneous control over both rows and columns. Key properties: display: grid, grid-template-columns: repeat(3, 1fr), grid-template-rows, gap: 1.5rem, grid-column: span 2.

Document Type Definition (DTD)

Not Attempted

An XML document is considered Well-Formed if it adheres to fundamental XML syntax rules (single root element, correctly nested tags, closing tags present, quoted attributes). An XML document is Valid if it is well-formed AND conforms to the constraints of a formal schema, such as a Document Type Definition (DTD).

1. Internal vs External DTD Declarations

  • Internal DTD: Defined directly within the XML document inside the <!DOCTYPE root [...]> block.
  • External DTD: Located in a separate .dtd file referenced via SYSTEM (private identifier/URL) or PUBLIC (standard identifier).

2. Element Type Declarations & Multiplicity Operators

Syntax: <!ELEMENT element-name (content-model)>

  • #PCDATA: Parsed Character Data (normal text checked by XML parser).
  • EMPTY: Element cannot contain child elements or character data (e.g., <!ELEMENT br EMPTY>).
  • ANY: Element can contain any mixture of elements and text.
  • , (Comma): Mandates sequential order: (name, email, phone).
  • | (Pipe): Represents choice (either/or): (credit_card | upi | netbanking).
  • ?: 0 or 1 occurrence (optional).
  • *: 0 or more occurrences (optional repeated).
  • +: 1 or more occurrences (mandatory at least once).
Complete DTD & Conforming XML Document XML & DTD 
<!-- course.dtd -->
<!ELEMENT course (code, title, instructor, student*)>
<!ELEMENT code (#PCDATA)>
<!ELEMENT title (#PCDATA)>
<!ELEMENT instructor (#PCDATA)>
<!ELEMENT student (name, rollNo)>
<!ELEMENT name (#PCDATA)>
<!ELEMENT rollNo (#PCDATA)>
<!ATTLIST course
  semester CDATA #REQUIRED
  credits (3|4) "4"
  id ID #REQUIRED>
<!ATTLIST student
  status (active|graduated) "active">

<!-- Conforming XML File -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE course SYSTEM "course.dtd">
<course semester="5" credits="4" id="c35302">
  <code>CS35302</code>
  <title>Web Technology</title>
  <instructor>Dr. Sharma</instructor>
  <student status="active">
    <name>Rahul Verma</name>
    <rollNo>2101034</rollNo>
  </student>
</course>

Dynamic HTML (DHTML) Concepts

Not Attempted

DHTML is not an independent programming language or W3C standard itself; rather, it is an umbrella term describing the strategic synthesis of four foundational technologies:

  1. HTML: Provides document content and semantic structure.
  2. CSS: Defines visual appearance, geometric positioning, and display states.
  3. JavaScript: Acts as the client-side scripting engine to react to user inputs.
  4. DOM (Document Object Model): The standardized API exposing HTML elements as programmatic objects that scripts can inspect and alter in real time.

1. Historical Evolution & Cross-Browser Challenges

During the 1990s browser wars between Netscape Navigator 4 and Microsoft Internet Explorer 4, each vendor introduced incompatible proprietary object models. Netscape introduced document.layers, while Microsoft created document.all. Developers were forced to write complex conditional sniffing routines:

Historical Legacy DHTML Sniffing vs Modern Standard JavaScript 
// Legacy 1990s Fragile DHTML:
function getLayer(id) {
  if (document.getElementById) return document.getElementById(id); // W3C Standard
  if (document.all) return document.all[id];                       // IE 4
  if (document.layers) return document.layers[id];                 // Netscape 4
}

// Modern W3C Standard DHTML:
const element = document.querySelector('#interactive-panel');
element.classList.toggle('active');

2. Classic DHTML Interactive UI Components

  • Image Rollovers: Swapping image src on mouseover / mouseout.
  • Accordion Panels: Expanding and collapsing content sections dynamically by toggling CSS height or display properties.
  • Modal Dialogs: Overlaying an accessible focused dialog box while dimming and locking background scrolling.
  • Drag-and-Drop Widgets: Listening to mouse/touch coordinates to dynamically update CSS transform: translate(x, y).

XML Schemas (XSD)

Not Attempted

While DTD provided initial schema validation, it suffered severe limitations: non-XML syntax, zero support for data types (treating everything as plain text #PCDATA), and no support for XML Namespaces. To solve this, the W3C published XML Schema Definition (XSD) in 2001.

1. Why XSD is Superior to DTD

  • Written in XML Syntax: Can be authored, parsed, transformed, and queried using standard XML tools and parsers.
  • Rich Data Types: Supports dozens of built-in primitive types (xs:string, xs:integer, xs:decimal, xs:boolean, xs:date, xs:anyURI).
  • User-Defined Constraints (Facets): Allows custom range bounds, lengths, and regular expression patterns (<xs:pattern>).
  • Namespace Support: Fully integrates with XML namespaces (targetNamespace, xmlns:xs="http://www.w3.org/2001/XMLSchema").

2. Simple Types vs Complex Types

  • Simple Type (<xs:simpleType>): Contains only text content; cannot have child elements or XML attributes. Often created by restricting a built-in type with facets.
  • Complex Type (<xs:complexType>): Can contain child elements, attributes, or mixed content.
Production XSD Schema with Facets & Compositors XML Schema (XSD) 
<?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema"
           targetNamespace="http://quantumuniversity.edu/webtech"
           xmlns="http://quantumuniversity.edu/webtech"
           elementFormDefault="qualified">

  <!-- Simple Type Restriction for Roll Number -->
  <xs:simpleType name="RollNumberType">
    <xs:restriction base="xs:string">
      <xs:pattern value="[0-9]{7}" />
    </xs:restriction>
  </xs:simpleType>

  <!-- Complex Type for Student -->
  <xs:element name="student">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="name" type="xs:string" />
        <xs:element name="rollNo" type="RollNumberType" />
        <xs:element name="marks" type="xs:decimal" minOccurs="0" />
      </xs:sequence>
      <xs:attribute name="semester" type="xs:positiveInteger" use="required" />
    </xs:complexType>
  </xs:element>

</xs:schema>

Object Models (DOM in XML)

Not Attempted

The XML Document Object Model (XML DOM) is a W3C standard programming interface that defines a platform- and language-neutral tree structure for accessing and manipulating XML documents. In the DOM, every component of an XML document (element, attribute, text, comment) is represented as a Node object.

1. XML DOM Node Types (nodeType Constants)

Node Type Constant Integer Value Description & Example
ELEMENT_NODE 1 An XML tag element (e.g., <student>).
ATTRIBUTE_NODE 2 An attribute inside a tag (e.g., id="101").
TEXT_NODE 3 The textual content enclosed inside an element.
CDATA_SECTION_NODE 4 Raw unparsed character data block (<![CDATA[...]>).
COMMENT_NODE 8 An XML comment (<!-- comment -->).
DOCUMENT_NODE 9 The root document object representing the entire XML file.

2. Parsing and Traversal in Client-Side JavaScript

Parsing XML Strings with DOMParser JavaScript 
const xmlString = `<courses>
  <course id="CS35302">
    <title>Web Technology</title>
    <credits>4</credits>
  </course>
</courses>`;

// Instantiate DOMParser
const parser = new DOMParser();
const xmlDoc = parser.parseFromString(xmlString, "application/xml");

// Inspect elements
const courses = xmlDoc.getElementsByTagName("course");
for (let i = 0; i < courses.length; i++) {
  const courseId = courses[i].getAttribute("id");
  const title = courses[i].getElementsByTagName("title")[0].textContent;
  console.log(`Course Code: ${courseId}, Title: ${title}`);
}

Presenting XML (CSS & XSLT)

Not Attempted

Raw XML documents contain purely structured semantic data with zero presentation instructions. To display XML content to end users in a browser, two standard mechanisms exist: CSS and XSLT (Extensible Stylesheet Language Transformations).

1. Method 1: Direct Styling with CSS

An XML document links to an external CSS stylesheet using a processing instruction at the top of the file: <?xml-stylesheet type="text/css" href="styles.css"?>.

Limitations of CSS for XML: CSS can only change visual styles (colors, fonts, displays). It CANNOT reorder nodes, filter subsets of elements, compute mathematical totals, or transform the document into another format.

2. Method 2: Document Transformation with XSLT

XSLT is a declarative, rule-based programming language that takes an XML source tree and transforms it into an HTML/XHTML document, plain text, or another XML schema. An XSLT processor matches template rules against nodes using XPath (XML Path Language).

XSLT Transformation Template XSLT Stylesheet 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
  <xsl:template match="/">
    <html>
      <head><title>University Course Catalog</title></head>
      <body>
        <h2>B.Tech CSE Courses</h2>
        <table border="1">
          <tr bgcolor="#7c3aed" style="color:white;">
            <th>Code</th><th>Title</th><th>Credits</th>
          </tr>
          <xsl:for-each select="catalog/course[credits >= 3]">
            <xsl:sort select="title" order="ascending" />
            <tr>
              <td><xsl:value-of select="@code" /></td>
              <td><xsl:value-of select="title" /></td>
              <td><xsl:value-of select="credits" /></td>
            </tr>
          </xsl:for-each>
        </table>
      </body>
    </html>
  </xsl:template>
</xsl:stylesheet>

Using XML Processors: DOM and SAX

Not Attempted

An XML Processor (Parser) is a software library that reads XML document files, verifies well-formedness and schema validity, and provides an API for application code to read or modify data. The two primary parsing paradigms are DOM and SAX.

1. DOM Parser (Document Object Model)

  • Model: Tree-based, in-memory object representation.
  • Operation: Reads the entire XML file into RAM, instantiates node objects for every tag and attribute, and builds an in-memory tree.
  • Pros: Allows random access, bidirectional navigation (parent/child/sibling), and live in-memory updates/serialization.
  • Cons: High memory consumption (often 5x to 10x the raw file size). Infeasible for gigabyte-scale datasets.

2. SAX Parser (Simple API for XML)

  • Model: Event-driven, streaming sequential push parser (created by David Megginson).
  • Operation: Reads the XML stream byte-by-byte from top to bottom. It does NOT construct an in-memory tree. As tags are encountered, it fires callback events to an application-supplied ContentHandler:
    • startDocument() and endDocument()
    • startElement(uri, localName, qName, attributes)
    • characters(char[] ch, int start, int length)
    • endElement(uri, localName, qName)
  • Pros: Constant memory footprint \(O(1)\), blazing fast speed, can parse multi-gigabyte files effortlessly.
  • Cons: Strictly forward-only, read-only; cannot navigate backwards or update nodes in place.

3. DOM vs SAX Architecture Comparison Matrix

Criteria DOM Parser (Tree Model) SAX Parser (Event Model)
Memory Consumption High \(O(N)\) — scales with file size Extremely Low \(O(1)\) — constant memory
Navigation Bidirectional random access across tree Forward-only, single-pass streaming
Document Modification Native in-place creation, editing, deletion Read-only (cannot mutate source tree directly)
Best Use Case Small-to-medium files requiring manipulation & XPath Large datasets, read-only parsing, log scanning
