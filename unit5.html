Semantic Web

Not Attempted

The vision of the Semantic Web was articulated in a famous 2001 Scientific American article by Tim Berners-Lee, James Hendler, and Ora Lassila. Traditional web pages are designed exclusively for human visual consumption (HTML markup tells the browser how to style text, but lacks semantic meaning). The Semantic Web aims to make web data machine-understandable, enabling autonomous software agents to perform sophisticated searching, reasoning, and automated tasks on behalf of users.

1. The Semantic Web Layer Cake

The architecture of the Semantic Web is visualized as a hierarchical stack of standards:

  1. URI / IRI & Unicode: Universal identification of entities across the web and internationalized character support.
  2. XML & XML Schema: Standardized syntax and data type definitions.
  3. RDF (Resource Description Framework): Graph data model of Subject-Predicate-Object statements representing facts.
  4. RDF Schema (RDFS) & OWL (Web Ontology Language): Formal representation of concepts, taxonomic class hierarchies, and logical relationships between entities.
  5. SPARQL: Standard query language to retrieve data across distributed RDF triplestores.
  6. Logic & Rule Engine (RIF / SWRL): Inference rules allowing machines to deduce new unstated facts from existing knowledge.
  7. Proof & Trust: Cryptographic verification and reputation mechanisms establishing data provenance.

2. The Four Principles of Linked Data

In 2006, Tim Berners-Lee outlined the four rules for publishing Linked Data on the Web:

  • Use URIs as names for things.
  • Use HTTP URIs so that people and software can look up those names (dereferencing).
  • When someone looks up a URI, provide useful information using standards (RDF, SPARQL).
  • Include links to other URIs so that agents can discover more related entities.

Widgets

Not Attempted

A Web Widget is a self-contained, portable, interactive client-side visual application component that can be embedded into any third-party web page without interfering with the hosting document (e.g., weather forecasts, stock tickers, interactive calculators, chat bubbles).

1. Modern Architecture: W3C Web Components

Historically, widgets were implemented via fragile <iframe> tags or global JavaScript script tags that polluted the global scope and suffered CSS style bleeding. Today, web widgets are built natively using the W3C Web Components suite:

  • Custom Elements: Standard APIs to define custom HTML tags with lifecycle callbacks (e.g., <course-badge>) using customElements.define().
  • Shadow DOM: Provides true encapsulation for markup and styles. Styles defined inside the Shadow Root cannot bleed out into the host page, and host page styles cannot unintentionally distort the widget.
  • HTML Templates (<template> & <slot>): Declares inert markup fragments that are not rendered until instantiated at runtime, with slots allowing consumers to inject custom text into predetermined positions.
Encapsulated Web Component Widget with Shadow DOM JavaScript 
class CourseBadge extends HTMLElement {
  constructor() {
    super();
    // Attach encapsulated Shadow DOM
    const shadow = this.attachShadow({ mode: 'open' });

    shadow.innerHTML = `
      <style>
        :host {
          display: inline-block;
          font-family: system-ui, sans-serif;
        }
        .badge {
          background: #7c3aed;
          color: white;
          padding: 0.35rem 0.75rem;
          border-radius: 9999px;
          font-size: 0.8125rem;
          font-weight: 600;
        }
      </style>
      <span class="badge">
        <slot>CS35302 – Web Technology</slot>
      </span>
    `;
  }
}

customElements.define('course-badge', CourseBadge);

Drag & Drop Mashups

Not Attempted

A Web Mashup is a composite web application that aggregates data, functionality, or multimedia from two or more independent external sources to create an entirely new, unified service. The historical breakthrough was HousingMaps (created in 2005 by Paul Rademacher), which merged Craigslist apartment listings with Google Maps to show rental locations visually on an interactive map.

1. Client-Side vs Server-Side Mashups

  • Client-Side Mashups: The user's browser makes asynchronous REST/Ajax calls directly to multiple external APIs (e.g., OpenWeatherMap and Mapbox) and stitches the responses together dynamically using JavaScript.
  • Server-Side Mashups: A backend server queries external APIs, performs data cleaning, schema reconciliation, and caching, and sends a single consolidated response payload down to the client. This avoids client-side CORS issues and protects private API secret keys.

2. Visual Drag & Drop Workflow Platforms

Tools like Yahoo! Pipes (in the 2000s) pioneered visual drag-and-drop mashups, enabling users without coding skills to connect data sources using graphical modules (Fetch, Filter, Sort, Merge). Today, visual workflow platforms like Zapier, Make, and n8n carry forward this paradigm.

3. HTML5 Native Drag and Drop API

Modern interactive mashup builders utilize HTML5 Drag and Drop:

HTML5 Native Drag and Drop Implementation JavaScript 
// 1. Draggable Widget Source
const widget = document.getElementById('map-widget-source');
widget.setAttribute('draggable', 'true');

widget.addEventListener('dragstart', (e) => {
  e.dataTransfer.setData('text/plain', 'widget:google-maps');
  e.dataTransfer.effectAllowed = 'copy';
});

// 2. Drop Target Canvas
const canvas = document.getElementById('mashup-canvas');

canvas.addEventListener('dragover', (e) => {
  e.preventDefault(); // Mandatory to allow drop!
  e.dataTransfer.dropEffect = 'copy';
});

canvas.addEventListener('drop', (e) => {
  e.preventDefault();
  const widgetType = e.dataTransfer.getData('text/plain');
  console.log(`Instantiating mashup component: ${widgetType}`);
  instantiateComponent(widgetType, e.clientX, e.clientY);
});

The Technology Behind These Applications – RDF

Not Attempted

The Resource Description Framework (RDF) is a W3C standard data model for representing information about web resources. In RDF, knowledge is structured not as relational tables or XML document hierarchies, but as a Directed, Labeled Graph of atomic assertions known as Triples.

1. The RDF Statement Triple: Subject – Predicate – Object

  • Subject: The resource being described. Identified by a URI or an anonymous blank node.
  • Predicate: The property, characteristic, or relationship. Always identified by a URI.
  • Object: The property value or target entity. Can be another URI (linking to another entity in the knowledge graph) or a Literal (typed string, integer, date).
RDF Turtle (Terse RDF Triple Language) Syntax Turtle 
@prefix ex: <http://quantumuniversity.edu/courses/> .
@prefix dc: <http://purl.org/dc/elements/1.1/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

# Subject                              Predicate          Object
ex:CS35302                             dc:title           "Web Technology"^^xsd:string ;
                                       dc:creator         "Dr. Sharma" ;
                                       ex:semester        "5"^^xsd:positiveInteger ;
                                       ex:taughtAt        <http://dbpedia.org/resource/Quantum_University> .

2. SPARQL (Protocol and RDF Query Language)

SPARQL is the standard SQL-like query language for querying graph patterns across RDF triplestores:

SPARQL Graph Query Example SPARQL 
PREFIX dc: <http://purl.org/dc/elements/1.1/>
PREFIX ex: <http://quantumuniversity.edu/courses/>

SELECT ?courseTitle ?semester
WHERE {
  ?course dc:title ?courseTitle .
  ?course ex:semester ?semester .
  FILTER(?semester >= 5)
}

Web-Based Information Systems

Not Attempted

A Web-Based Information System (WBIS) is an enterprise software system that harnesses Internet technologies and protocols to collect, store, process, and distribute business data to support decision-making, transactional processing, and operational control.

1. The Three-Tier Enterprise Architecture

Tier Layer Core Responsibilities Typical Technologies
Presentation Tier (Client Layer) User interface, collecting inputs, client-side validation, rendering responses. Web Browsers, HTML5, CSS3, JavaScript, React, Mobile Apps.
Application / Logic Tier (Middle Layer) Business rules execution, transaction coordination, security enforcement, orchestrating workflows. Node.js, Java Spring Boot, Python Django/FastAPI, Ruby on Rails, C# .NET Core.
Data Tier (Persistence Layer) Persistent storage, ACID transactions, data retrieval, indexing, backups. PostgreSQL, MySQL, Oracle, MongoDB, Redis, Cassandra.

2. Scalability Engineering and CAP Theorem

  • Horizontal Scaling: Adding more web server nodes behind an intelligent Load Balancer (NGINX, HAProxy, AWS ALB) rather than buying a bigger machine (Vertical Scaling).
  • Connection Pooling: Maintaining a cache of pre-established database connections to eliminate the expensive latency of handshakes for every HTTP request.
  • Brewer's CAP Theorem: States that a distributed data store can simultaneously provide at most two of the following three guarantees: Consistency (every read receives the most recent write), Availability (every request receives a non-error response), and Partition Tolerance (system continues operating despite network message drops). In real-world networks where partitions inevitably occur, systems must choose between CP and AP.

The Technology Behind These Applications – Search Engines

Not Attempted

A Web Search Engine is an information retrieval system designed to discover, index, and rank web resources in response to user queries. The operational pipeline consists of three sequential phases: Crawling, Indexing, and Ranking.

1. Crawling and Indexing

  • Web Crawling: Automated bots (such as Googlebot) download pages, parse hyperlinks, and add new URLs to a priority frontier queue. Crawlers adhere to site crawling permissions via robots.txt and XML Sitemaps.
  • Text Normalization: Raw HTML is stripped of tags, lowercased, tokenized into words, stripped of stop words (the, is, at), and reduced to word roots via linguistic stemming (e.g., Porter Stemmer).
  • Inverted Index: The foundational data structure of search engines. Instead of mapping a Document → Words, an Inverted Index maps each Term → List of Document IDs where that term appears, along with positional offsets and frequencies.

2. Ranking: TF-IDF and Google PageRank

Relevance scoring combines textual relevance with link authority:

  • TF-IDF (Term Frequency - Inverse Document Frequency): Evaluates how important a word is to a document in a collection: \[ ext{TF-IDF}(t, d, D) = ext{TF}(t, d) imes \log\left( rac{|D|}{|\{d \in D : t \in d\}|} ight) \] Words appearing frequently in one document but rarely across the entire corpus receive the highest scores.
  • PageRank Algorithm (Page and Brin, 1998): Interprets a hyperlink from page \(A\) to page \(B\) as a vote of confidence. The PageRank \(PR(A)\) is formulated under the Random Surfer Model: \[ PR(A) = rac{1 - d}{N} + d \sum_{i \in M(A)} rac{PR(i)}{L(i)} \] Where \(d\) is the damping factor (typically \(0.85\)), \(N\) is total pages, \(M(A)\) is the set of pages linking to \(A\), and \(L(i)\) is the outbound link count of page \(i\).

The Technology Behind These Applications – Recommender Systems

Not Attempted

Recommender Systems are algorithmic information filtering engines that predict the rating or preference a user would give to an item, presenting personalized suggestions across vast catalogs (Amazon products, Netflix movies, Spotify tracks).

1. Primary Recommender Paradigms

  • Collaborative Filtering (CF): Generates recommendations based solely on historical interaction patterns across users. Does not require understanding item contents.
    • User-Based CF: Finds "peers" with similar past rating histories and recommends items they enjoyed.
    • Item-Based CF: Calculates similarity between items based on how they were co-rated by users (computationally more stable than user-based CF).
  • Content-Based Filtering: Recommends items that share structural or textual attributes (genres, directors, keywords) with items the user has previously rated highly. Uses vector space cosine similarity between user profile vectors and item attribute vectors.
  • Hybrid Recommenders: Combines collaborative and content-based approaches to offset the weaknesses of each (e.g., Netflix blending collaborative viewing patterns with genre tags).

2. The Cold Start Problem and Similarity Metrics

The Cold Start Problem occurs when new items have zero ratings or new users have zero interaction history, preventing collaborative filtering from making predictions. Content-based heuristics are used as fallback.

Similarity between user rating vectors \( ec{u}\) and \( ec{v}\) is measured using Cosine Similarity: \[ ext{Cosine}( ec{u}, ec{v}) = rac{ ec{u} \cdot ec{v}}{\| ec{u}\| \| ec{v}\|} = rac{\sum_{i} u_i v_i}{\sqrt{\sum_{i} u_i^2} \sqrt{\sum_{i} v_i^2}} \]

Web Mining

Not Attempted

Web Mining is the application of data mining, machine learning, and statistical analysis techniques to automatically discover patterns, extract actionable knowledge, and uncover insights from World Wide Web resources and user interactions.

1. The Three Primary Branches of Web Mining

Web Mining Category Source Data Inspected Key Algorithms & Practical Applications
Web Content Mining Unstructured and semi-structured content: HTML text, metadata, images, and audio. Natural Language Processing (NLP), Sentiment Analysis of customer reviews, text classification, and Named Entity Recognition (NER).
Web Structure Mining The hyperlink topology graph connecting web pages, documents, and social accounts. Kleinberg's HITS Algorithm (Hubs and Authorities), Google PageRank, community detection, identifying authoritative nodes.
Web Usage Mining Web server access logs, clickstream tracking data, referrer headers, and user cookies. Sessionization (identifying user sessions from log streams), path completion analysis, shopping cart abandonment modeling, e-commerce conversion funnel optimization.
🔍
Kleinberg's HITS Algorithm (Hubs & Authorities) Developed by Jon Kleinberg, HITS identifies two types of important pages:
  • Authorities: Web pages containing prominent, trusted content on a topic (pointed to by many hubs).
  • Hubs: Web pages containing curated links pointing to multiple authoritative resources on a topic. Authorities and hubs exhibit a mutually reinforcing relationship!
