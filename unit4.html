Topic 4.1 • Syllabus Section

Interactive and Social Web: Blogs

Not Attempted

A Blog (short for Weblog, coined by Jorn Barger in 1997 and shortened by Peter Merholz in 1999) is a regularly updated personal or corporate website where discrete content entries (posts) are displayed in reverse chronological order (newest posts appearing at the top).

1. Fundamental Architecture and Components of a Blog

  • Post Entry: Title, author attribution, publish timestamp, rich body content, and categorized tags.
  • Permalink (Permanent Link): A static, unique URL pointing permanently to a specific blog post, ensuring hyperlinks remains valid even when new content shifts the post off the front page.
  • Comments System: An interactive discussion forum nested beneath each post, enabling two-way conversation between author and global readers.
  • Trackback & Pingback: Peer-to-peer notification mechanisms alerting Author A when Author B writes a new blog post linking to Author A's work.
  • Blogroll: A curated list of outbound hyperlinks to other related blogs recommended by the author, forming the conversational interconnected "Blogosphere".

2. The Evolution of Blog Content Management Systems (CMS)

Early blogs were manually edited static HTML files. The introduction of dynamic databases and server-side scripting produced automated CMS platforms (WordPress, Movable Type, Drupal). Today, blogging has evolved into modern Headless CMS systems (Strapi, Sanity) coupled with Static Site Generators (Next.js, Gatsby, Hugo) for blazing speed, and Microblogging platforms (such as X/Twitter) for high-frequency short-form updates.

Interactive and Social Web: Wikis

Not Attempted

A Wiki is a collaborative hypertext publication system designed to enable anyone with browser access to freely create, edit, modify, and interlink pages using simplified markup syntax. The first wiki software, WikiWikiWeb, was created in 1995 by Ward Cunningham, named after the Hawaiian word "wiki", meaning quick.

1. Architectural Pillars of a Wiki System

  • Open Collaborative Editing: Any authorized visitor can click an "Edit" button and immediately update the page content directly in their browser.
  • Simplified Wikitext Markup: Uses lightweight formatting rules (e.g., [[Topic]] to create an instant internal hyperlink) rather than verbose raw HTML tags.
  • Complete Revision History & Audit Trail: Every single edit is permanently preserved in the underlying database with editor username/IP, timestamp, and summary.
  • Visual Diff Engine: Highlights exact inline additions (green) and deletions (red) between any two historical revisions.
  • One-Click Rollback: Administrators can instantly revert vandalism or erroneous edits to the previous stable revision.
  • Conflict Resolution: Employs optimistic locking or 3-way merge algorithms when two editors attempt to save changes to the same page concurrently.
🌐
The Wikimedia / Wikipedia Paradigm Wikipedia (founded in 2001 by Jimmy Wales and Larry Sanger) runs on the open-source MediaWiki software. Its immense success proves that open collaborative crowdsourcing, guided by core policies such as Neutral Point of View (NPOV) and Verifiability, can produce comprehensive, high-quality knowledge repositories.

Interactive and Social Web: Social Networking Sites

Not Attempted

Social Networking Sites (SNS) are web-based platforms that enable individuals to (1) construct a public or semi-public profile within a bounded system, (2) articulate a list of other users with whom they share a connection, and (3) view and traverse their list of connections and those made by others within the system (boyd and Ellison, 2007).

1. The Social Graph Data Model

At the architectural core of any social network lies the Social Graph, modeled as a mathematical graph \(G = (V, E)\):

  • Vertices / Nodes (\(V\)): Individual entities within the system: Users, Pages, Groups, Photos, Events.
  • Edges (\(E\)): Relationships connecting the nodes. Can be Undirected (reciprocal friendship, e.g., Facebook) or Directed (asymmetrical follower model, e.g., Twitter/X, Instagram, GitHub).

2. Feed Generation: Fan-Out-On-Write vs Fan-Out-On-Read

Architecture Model How it Operates Advantages & Trade-offs
Fan-Out-on-Write (Push Model) When user A posts a status, background workers instantly push the post ID into the pre-computed timeline cache of every single follower. Fast Reads: When a follower opens their app, their home feed is immediately available from memory cache. Disadvantage: Highly inefficient for "celebrity" accounts with 50 million followers (the Celebrity Problem).
Fan-Out-on-Read (Pull Model) When user B requests their timeline, the system dynamically queries the posts of all followed users, sorts them, and delivers the merged feed. Fast Writes: Posting takes zero background worker load. Disadvantage: Expensive, slow database read queries at feed retrieval time.
📈
Network Effects & Metcalfe's Law Metcalfe's Law states that the value of a telecommunications network is proportional to the square of the number of connected users (\(V \propto n^2\)). This explains why social networks exhibit powerful viral growth dynamics and winner-take-all market consolidation.

The Technology Behind the Application – AJAX

Not Attempted

In modern interactive social web applications, AJAX is the underlying architectural engine that enables seamless Single Page Applications (SPAs). Rather than treating each click as a brand new document download, SPAs load an initial HTML/JS shell once and continuously fetch and mutate data in the background.

1. Client-Side Routing and the HTML5 History API

To prevent full page reloads while maintaining shareable URLs and browser back/forward button history, SPAs utilize the HTML5 History API:

  • history.pushState(stateObj, title, url): Adds a new entry to the browser session history without triggering a network page reload.
  • history.replaceState(...): Replaces the current history entry.
  • window.addEventListener('popstate', callback): Detects when the user clicks the browser Back or Forward buttons, allowing the client-side router to render the corresponding component.

2. Infinite Scrolling with IntersectionObserver

Modern feeds (Instagram, LinkedIn) eliminate pagination buttons using infinite scrolling. Instead of attaching expensive scroll event listeners, modern browsers utilize the IntersectionObserver API to asynchronously detect when a sentinel footer element scrolls into view:

High-Performance Infinite Scroll with IntersectionObserver JavaScript 
let page = 1;
const sentinel = document.getElementById('scroll-sentinel');

const observer = new IntersectionObserver(async (entries) => {
  const [entry] = entries;
  if (entry.isIntersecting) {
    // User reached the bottom of feed
    page += 1;
    const response = await fetch(`/api/feed?page=${page}`);
    const newPosts = await response.json();
    
    appendPostsToFeed(newPosts);
  }
}, { rootMargin: '200px' }); // Pre-fetch 200px before user hits bottom

observer.observe(sentinel);

The Technology Behind the Application – RSS

Not Attempted

RSS (Really Simple Syndication / Rich Site Summary) is an XML-based data format that allows content publishers to distribute automated feeds of frequently updated content (blog posts, news headlines, podcast episodes) directly to feed aggregators and readers.

1. Structure of an RSS 2.0 Document

An RSS document is wrapped in a top-level <rss version="2.0"> element containing a single <channel> element with three mandatory channel sub-elements:

  • <title>: The name of the channel / feed.
  • <link>: The corresponding HTML website URL.
  • <description>: A phrase or sentence describing the channel.
Standard RSS 2.0 Feed with Podcasting Enclosure RSS 2.0 XML 
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom">
  <channel>
    <title>Quantum University WebTech Feed</title>
    <link>https://quantumuniversity.edu/webtech</link>
    <description>Latest syllabus updates and engineering notes</description>
    <language>en-us</language>
    <pubDate>Wed, 18 Nov 2026 09:00:00 GMT</pubDate>

    <item>
      <title>Unit 4: Interactive and Social Web Notes Released</title>
      <link>https://quantumuniversity.edu/webtech/unit4</link>
      <description>Comprehensive study materials on Blogs, Wikis, and Rails.</description>
      <guid isPermaLink="true">https://quantumuniversity.edu/webtech/unit4#overview</guid>
      <pubDate>Wed, 18 Nov 2026 08:30:00 GMT</pubDate>
      <!-- Enclosure tag enabling podcasting -->
      <enclosure url="https://quantumuniversity.edu/audio/unit4-lecture.mp3"
                 length="15420300"
                 type="audio/mpeg" />
    </item>
  </channel>
</rss>
🎙️
The Secret Behind Podcasting: The Enclosure Tag Podcasting does not use a proprietary streaming protocol. In 2000, Dave Winer added the <enclosure> tag to the RSS specification at the request of Adam Curry. By including the media URL, file size in octets, and MIME type, podcatchers (Apple Podcasts, Spotify) automatically download new audio files in the background!

The Technology Behind the Application – Syndication

Not Attempted

Web Syndication is the process of making web feeds available from a source site to provide other people with a summary of the site's recently added content. Beyond basic RSS 2.0, the broader syndication architecture encompasses the Atom Syndication Format, OPML subscription lists, and real-time push protocols like WebSub.

1. Atom Syndication Format (IETF RFC 4287)

Published in 2005 by the IETF to resolve ambiguities and licensing disputes in RSS, Atom provides a cleaner XML namespace (xmlns="http://www.w3.org/2005/Atom"). Key structural differences from RSS:

  • Enclosing element is <feed> (instead of <rss><channel>).
  • Entries are labeled <entry> (instead of <item>).
  • Mandatory globally unique IRI identifier: <id>.
  • Standardized ISO 8601 timestamps: <updated>2026-11-18T09:00:00Z</updated>.

2. OPML (Outline Processor Markup Language)

An XML format used to export and import entire lists of RSS/Atom feed subscriptions between different feed reader applications (e.g., Feedly, Inoreader).

3. WebSub (PubSubHubbub) Real-Time Push Syndication

Traditional RSS requires clients to constantly poll servers (e.g., every 15 minutes) using HTTP Conditional GET (If-Modified-Since or ETag yielding 304 Not Modified). WebSub (a W3C recommendation) replaces polling with a 3-party publish-subscribe architecture:

  1. Publisher informs a Hub whenever new content is published.
  2. The Hub immediately makes an HTTP POST webhook call to all subscribed readers, delivering new items with millisecond latency!

Ruby on Rails

Not Attempted

Ruby on Rails (often simply Rails) is an open-source model-view-controller (MVC) web application framework written in the Ruby programming language. Created in 2004 by David Heinemeier Hansson (DHH), Rails revolutionized modern web development by introducing opinionated software design philosophies.

1. Guiding Architectural Philosophies

  • Convention over Configuration (CoC): Rails makes sensible assumptions about database schema naming, routing, and directory structures. If a model class is named Student, Rails automatically binds it to the database table students without requiring hundreds of lines of XML mapping files.
  • Don't Repeat Yourself (DRY): Every piece of knowledge must have a single, unambiguous representation within a system.

2. The Rails MVC Architecture

  • Model (Active Record): Represents business data and logic. Implements the Active Record design pattern where a database row is wrapped in a Ruby object with built-in validation, lifecycle callbacks, and relational associations (has_many, belongs_to).
  • View (Action View): Renders HTML or JSON responses, typically authored using Embedded Ruby (.html.erb) templates.
  • Controller (Action Controller): Accepts HTTP requests, interrogates parameters, coordinates with models to query/save data, and dispatches data to views.
Rails Active Record Model & Controller Ruby on Rails 
# app/models/student.rb
class Student < ApplicationRecord
  has_many :test_scores, dependent: :destroy

  validates :name, presence: true
  validates :roll_no, presence: true, uniqueness: true
end

# app/controllers/students_controller.rb
class StudentsController < ApplicationController
  def show
    @student = Student.find(params[:id])
    render json: @student, include: :test_scores
  end

  def create
    @student = Student.new(student_params)
    if @student.save
      render json: @student, status: :created
    else
      render json: @student.errors, status: :unprocessable_entity
    end
  end

  private
  def student_params
    params.require(:student).permit(:name, :roll_no, :semester)
  end
end

Open APIs

Not Attempted

An Open API (also referred to as a Public API) is a publicly available application programming interface that provides developers with programmatic access to a proprietary software application or web service. Open APIs power modern mashups, third-party integrations, and ecosystem platforms (e.g., Stripe, Google Maps, OpenWeather, GitHub).

1. Architectural Pillars of Production Open APIs

  • RESTful JSON Interfaces: Utilizes standard HTTP verbs (GET, POST, PUT, DELETE), resource-oriented URIs, and JSON payloads.
  • OpenAPI Specification (OAS / Swagger): A vendor-neutral, machine-readable description format (YAML or JSON) defining endpoints, parameters, request bodies, and response schemas.
  • Authentication & Authorization: Implemented via API Keys passed in headers, Bearer Tokens, or decentralized OAuth 2.0 Authorization Frameworks.
  • Rate Limiting: Enforces quota limits to prevent denial-of-service abuse and maintain infrastructure stability (e.g., 100 requests per minute). Exceeded quotas return HTTP status 429 Too Many Requests with Retry-After response headers.
  • Idempotency Keys: Using an Idempotency-Key header to ensure that network retries of financial or state-altering requests (like charging a credit card) do not execute twice.
